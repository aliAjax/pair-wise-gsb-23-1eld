# hxwl-09 半导体洁净室巡检（断网续作 / 合并 / 校准换批 / 崩溃恢复）

夜班巡检员在**无网洁净室**用粒子计数器记录，回办公区才与复核员整理房间异常。
本应用把这套工作流做成可运行的演示：IndexedDB 本地库 + 出站队列 + 模拟服务器 + 同步引擎。

## 本地运行

```bash
npm install
npm run dev       # http://localhost:5109
npm test          # 10 个纯逻辑/端到端测试
npm run build     # tsc 类型检查 + 生产构建
```

## 业务规则与实现位置

| 规则 | 实现 |
| --- | --- |
| 巡检记录、异常处理单、校准批次断网可续作 | 全部先写 IndexedDB（`src/store/idb.ts`），变更进出站队列（OutboxOp），在线时才推送 |
| 同房间同时段两份记录：**原始值都保留**、标出差异 | `buildConflictViews` 按 `房间|时段` 分组，并排展示各端 0.5µm/5µm 原值与“不一致”标记 |
| 复核员按**现场封条时间**选用一份 | `orderRecordsBySeal` 仅按 `sealedAt` 排序并给出建议；选择记录为 `ConflictResolution` |
| 后上传时间不能盖掉现场先后 | 记录带两个时间：`sealedAt`（现场事实，永不被改写，`mergeRecord` 强制保留）与 `capturedAt`（录入/上传，仅展示） |
| 校准批次变化：未审批结论失效重算 | `refreshTicket` 对 pending 单按当前最新已审批批次重算，依据变化时写入 `invalidated` + `recomputed` 轨迹 |
| 已确认处理单保留当时阈值和校准编号 | 确认时把 `TicketBasis`（阈值表、校准编号、封条时间）冻结到单据上；之后 `refreshTicket` 原样返回 |
| 浏览器崩溃后从最近完整交接批次恢复 | `HandoverBatch.checkpointAt` 为检查点；`planRecovery` 只重放检查点之后未 ack 的操作，未完成项=进行中批次内记录 |
| 重复提交不能多出处理单 | 处理单编号确定性 `T|房间|时段`；操作带幂等键，服务器 `appliedOpIds` 去重，版本号防旧盖新 |
| 旧记录缺校准编号先待核、不参加审批 | 记录 `calibrationId == null` ⇒ 单据无 basis、审批被 `canApprove` 拦截；补核后退出待核 |

## 模块

```
src/domain/types.ts      领域模型（记录/处理单/校准批次/交接批次/出站操作）
src/domain/logic.ts      纯逻辑：冲突分组、阈值判定、换批重算、冻结、恢复计划、实体合并（可独立测试）
src/store/idb.ts         IndexedDB 封装
src/store/mockServer.ts  localStorage 模拟服务器：幂等应用 + 增量拉取
src/store/store.ts       应用状态、对账引擎 reconcile、同步 syncNow、种子与崩溃恢复
src/App.tsx              巡检录入/冲突选用/复核审批/校准批次/日志队列 四个页签
tests/                   Node 测试（esbuild 即时转译，无需另起编译）
```

## 建议演示路径

1. **断网**（右上“断开网络”）→ 巡检端A 记录 CR-1201；点“模拟巡检端B 也记了同一房间”（封条更早、上传更晚）。
2. **恢复网络** → “立即同步合并” → 冲突卡片里两份原始值并排、差异标出、默认建议封条最早的一份 → 复核员选用。
3. “校准批次”页发布 **CAL-2026Q4**（ISO 5 的 0.5µm 阈值 3520→4200）：未审批超限单出现“失效/重算合格”轨迹；先确认一张单再换批，可见其冻结旧阈值与编号。
4. 对未审批单点“重复提交”，服务器去重计数增加，处理单始终一张。
5. 种子数据里 CR-3305 是缺校准编号的旧记录（待核，无法审批），点“补核”后才可进入审批。
6. 点“模拟浏览器崩溃”：重启横幅显示从最近完整交接批次恢复、只重放未完成操作；先“完成交接批次”再崩溃，检查点后没有残留操作。
